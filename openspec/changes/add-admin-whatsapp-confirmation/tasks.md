## Delivery and TDD protocol

Implement the four stacked-to-main PR stages in order. Each work unit is independently rollbackable and targets ≤400 changed lines; stop for replanning before implementation if an honest estimate exceeds that budget. The parent has selected `auto-chain` with `stacked-to-main`; do not mix chain strategies or compress tests, documentation, or PDF content to meet the budget.

For **every implementation unit**, record the following evidence in its PR/commit: **RED**—add the named failing Vitest test(s) first and capture the failing command/result; **GREEN**—make only the smallest production change that passes; **TRIANGULATE**—add the named boundary/negative/concurrency case and capture its result; **REFACTOR**—remove duplication without behavior change and rerun the focused command. Include the stated runtime harness result, or explicitly record `N/A` only where the unit has no runtime boundary. Keep tests with the code they verify and use one outcome-oriented Conventional Commit per completed unit.

Baseline validation after dependency work: `pnpm test`, `pnpm check`, and `pnpm build`. Database tests must use local in-memory libSQL and the real migration runner; automated tests must not use live Turso credentials or an Evolution instance.
